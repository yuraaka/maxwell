# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root.
- `docs/adr/` for architectural decision records.

Before exploring, read the glossary and ADRs relevant to the work.
If they do not exist, proceed silently. Domain-modeling creates them as terms and decisions are resolved.

Use glossary terminology when naming domain concepts in issues, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the term or note the gap for domain-modeling.

If a proposal conflicts with an existing ADR, identify the ADR and explain the proposed change rather than silently overriding it.
